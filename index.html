Project Status

Use case

Install Arch Linux unattended with a single Bash script: into a folder, onto a partition or onto a whole disk including partitioning, from any Linux system. Everything the script needs and does not get via command line is asked for once at the start, afterwards the installation runs on its own. Downloaded packages are cached, so further installations also work offline. Sourced as a library, its functions are the base for own installers.

Not to be confused with the guided installer "archinstall" shipped by Arch Linux itself.

Quick start

Download the script, it fetches its only library bashlink by itself:

curl \
    --output archinstall.sh \
    https://raw.githubusercontent.com/thaibault/archinstall/main/archinstall.sh
chmod +x archinstall.sh

Alternatively install it via "npm install archinstall" or on Arch Linux from the AUR as package "arch-install". Both provide it as command "arch-install" to not conflict with the official "archinstall" package. Then run it as root, e.g. from the Arch Linux live system:

./archinstall.sh --host-name my-system --target /dev/sdb --auto-partitioning

Without "--verbose" only problems are reported, "--debug" additionally shows the output of all used tools. "--help" lists all options with their current defaults.

Targets

"--target" decides where the new system goes, "archInstall" in the current folder by default:

  • A folder, e.g. "--target /tmp/system": Installs a complete system into it, useful to prepare or modify an image before using it.
  • A whole disk, e.g. "--target /dev/sdb": With "--auto-partitioning" a 2 GB UEFI boot partition and a system partition using the rest are created. Without, you partition yourself: the first partition becomes boot, the second the system.
  • A single partition, e.g. "--target /dev/sdb2": Installs only the system, e.g. next to an existing one.

The system partition is formatted with Btrfs (subvolume "root"), the boot partition with FAT32. systemd-boot is installed and registered in the firmware as boot entry "archLinux" (see "--boot-entry-label"), so the new system boots without further steps. "--boot-partition-label" and "--system-partition-label" change the partition labels. "--encrypt" encrypts the system partition with the password given via "--password". It is unlocked automatically on boot via a key file on the boot partition.

Configuration

The new system is configured completely: keyboard layout, time zone, time synchronization, host name, users, network services, package signatures and mirrors. Every option also has a short form, e.g. "-n" for "--host-name":

./archinstall.sh \
    --additional-packages vim openssh \
    --country-with-mirrors Germany \
    --host-name my-system \
    --keyboard-layout de-latin1 \
    --local-time Europe/Berlin \
    --needed-services sshd \
    --target /dev/sdb \
    --auto-partitioning \
    --user-names alice bob
  • Users get their name as initial password, root gets "root" or the value of "--password". Change them after the first login.
  • "--add-common-additional-packages" adds "base-devel", "python" and "sudo". Options with several values can also be repeated.
  • "--prevent-using-existing-pacman" installs with a freshly downloaded pacman instead of the host's one, e.g. if the host uses custom repositories.
  • "-A /dev/sdb" is short for "--auto-partitioning --debug --host-name archlinux --target /dev/sdb".

Installing offline

Every installation stores the downloaded packages in "archInstallCache" (or the folder given via "--cache-path"). Further installations with this cache work without network, e.g. from a USB stick carrying script and cache. Additional packages have to be in the cache as well. On a live system the current folder lives in memory, so point "--cache-path" to real storage.

Without root permissions

With "fakeroot" and "fakechroot" installed, an existing folder can be used as target without root permissions. File ownership can not be set this way, so the result is packed into a tar archive which has to be extracted as root before use.

Use as library

Sourced instead of executed, the script only defines its variables and functions (prefixed with "ai_" and "AI_"). Own installers can adjust them and run the installation via "ai_main":

#!/usr/bin/env bash
source archinstall.sh

AI_NEEDED_SERVICES+=(sshd)
ai_main --additional-packages openssh "$@"

The API documentation describes all functions.

Custom installation media

"pack-into-archiso" builds an Arch Linux ISO image which contains archinstall (and bashlink if installed) in its live system, so it is available offline right after booting as "archinstall.sh" or via the shortcut "install". The boot configuration of the original image is kept. It needs root permissions, "xorriso" ("libisoburn") and "squashfs-tools":

./pack-into-archiso.sh \
    ./archlinux-x86_64.iso \
    ./archlinux-with-archinstall.iso \
    --keyboard-layout us

"--keyboard-layout" sets the console keyboard layout of the live system, "--squash-filesystem-compressor" the compression of its file system ("gzip" by default).
